# Log File Naming Contract: 轮转文件命名

**Feature**: `006-log-trace-level`

## 命名规则

```text
{log_dir}/{file_prefix}.log.{YYYY-MM-DD}.{N}
```

- `YYYY-MM-DD`：日志内容所属的本地日期
- `N`：当天序号，十进制、不补零，从 `1` 开始
- 活跃文件仍为 `{log_dir}/{file_prefix}.log`

## 生成算法（语义）

1. 确定轮转日期：
   - 大小轮转：使用当前本地日期
   - 跨天轮转：使用被归档日志所属的日期（旧 `current_date`）
2. 令 `N = 1`
3. 拼接候选路径；若已存在，则 `N = N + 1` 重试
4. 找到不存在的名称后重命名活跃文件
5. 打开新的活跃文件并将大小计数归零
6. 执行现有保留清理

**保证**：任何已存在的轮转文件都不会被覆盖。

## 示例

```text
stunserver.log                      # 活跃日志
stunserver.log.2026-10-31.1         # 10-31 第 1 次轮转
stunserver.log.2026-10-31.2         # 10-31 第 2 次轮转
stunserver.log.2026-10-31.10        # 10-31 第 10 次轮转（不补零）
stunserver.log.2026-11-01.1         # 次日第 1 次轮转（序号重置）
```

## 边界场景

| 场景 | 期望 |
|------|------|
| 当天首次轮转 | 生成 `.当天日期.1` |
| `.1` 已存在 | 生成 `.2`，不覆盖 |
| 服务重启后再次轮转 | 扫描现有文件继续递增 |
| 跨过午夜后首次写入触发轮转 | 旧文件以旧日期归档；当天后续轮转为 `.新日期.1` |
| 目录中存在历史文件 `stunserver.log.2026-10-29`（无序号） | 不冲突；保留清理仍将其视为轮转文件 |
| 轮转文件数超过 `retention_days` | 按修改时间删除最旧文件，规则不变 |

## 与保留策略的关系

- 匹配前缀仍为活跃文件名（如 `stunserver.log`）
- 历史无序号文件与新带序号文件统一参与清理
- 本特性不改变 `retention_days` 的含义与默认值（30 天）
